# Правила работы с репозиторием Local Server Manager

## Выпуск новой версии

Пользователь запускает приложение прямо из `dist-release\Local Server Manager.exe`. После каждой
пересборки (`npm run tauri build`) папка приводится к одному и тому же виду, а приложение
перезапускается на свежей версии.

1. **Имя файла всегда одно: `dist-release\Local Server Manager.exe`.** Новая сборка
   (`src-tauri\target\release\local-server-manager.exe`) кладётся под этим именем, без номера версии.
2. **Прошлые версии не хранятся.** Старые exe и установщики из `dist-release` удаляются.
   Рядом остаётся только установщик той же, свежей версии (`…_x64-setup.exe`).
3. **После сборки свежая версия перезапускается.** Работающий exe занят и не перезаписывается,
   поэтому порядок такой:
   - запомнить, какие серверы сейчас работают под приложением (дочерние процессы, кроме
     `msedgewebview2.exe` и `conhost.exe`), чтобы назвать их пользователю;
   - завершить приложение (`Stop-Process` по процессу из `dist-release`). Его серверы при этом
     гаснут: они привязаны к приложению через Job Object, это ожидаемо;
   - заменить `Local Server Manager.exe`;
   - запустить его через `explorer.exe "<путь к exe>"`, а не `Start-Process`: так приложение
     получает обычное окружение пользователя, а не окружение оболочки агента (в нём, например,
     задан `NO_COLOR`, и серверы запускались бы без цветов);
   - сообщить пользователю, какие серверы были остановлены перезапуском.

## Проверки рядом с работающим приложением

Приложение не допускает второго экземпляра. Чтобы проверить сборку, не трогая рабочее приложение
пользователя, проверочный экземпляр запускается под другим идентификатором и со своей папкой
настроек (`LSM_DATA_DIR`):

```bash
npm run tauri -- dev --config <файл с {"identifier":"com.localservermanager.devcheck"}>
```

Рабочее приложение останавливается только на шаге перезапуска из раздела выше.
